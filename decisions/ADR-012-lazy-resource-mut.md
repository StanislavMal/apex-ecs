# ADR-012: `World::resource_mut` отдаёт ленивый `ResMut` (взятие ≠ изменение)

**Дата:** 2026-08-06 · **Статус:** принято ·
**Происхождение:** кампания CORE_ECONOMY (реестр PE-C6)

## Контекст

Компонентная модель ядра давно ленивая (A13/RT-1: `Mut<T>` штампит тик на
`deref_mut`), но ресурсный золотой путь `World::resource_mut::<T>() -> &mut T`
штампил тик ПРИ ВЗЯТИИ. Следствия: `Changed`-гейты по ресурсам срабатывали на
доступ-без-правки, а служебные ресурсы висели вечно «изменёнными» —
`stage_steps` ежекадрово дренировал `FixedTime` (запись в аккумулятор даже при
нуле шагов), `apply_state_transition` ежекадрово писал `None` в `NextState` и
чистил пустые `StateTransitions`.

## Решение

- `World::resource_mut`/`try_resource_mut` возвращают **`ResMut<'_, T>`**
  (Bevy-паритет `World::resource_mut -> Mut<T>`): штамп — на `deref_mut`.
- `ResMut::set_if_neq` (паритет компонентного `Mut::set_if_neq`): равное
  значение не пишет и не штампит. `ResMut::into_inner` — сознательный выход в
  `&mut T` = штамп (паритет `Mut::into_inner`); канон для сайтов, отдающих
  `&mut` наружу.
- Низкоуровневый `Resources::get_mut(tick)` ОСТАЁТСЯ явным eager-API
  (задокументирован) — не золотой путь.
- Служебные писатели переведены на «пиши только при деле»: `stage_steps` не
  трогает аккумулятор без шага; `apply_state_transition` не пишет на холостом
  кадре; движковый `App::update` не аккумулирует dt=0.

## Последствия

- Тип-миграция обоих репо: механический свип (движок — 109 файлов, `let mut` +
  точечные `into_inner`); гейт `cargo check --workspace --all-targets
  --all-features` (урок TD-203).
- `Changed`-гейты по ресурсам теперь достоверны: движковый PE.6-кэш prepare()
  может доверять тикам ресурсов (пересмотр его консервативных допущений — за
  движком).
- Тест-канон: `resource_mut_acquisition_is_not_a_change`.
