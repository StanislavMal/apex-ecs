# ADR-009 — Реактивная обвязка для динамических потребителей: тики ресурсов, ручной тик-доступ, serde-путь из Lua

**Статус:** принят 2026-07-14 (волна RT, потребитель — кампания UI_ARCHITECTURE движка,
фаза UI.5 «биндинги/реактивность»; решения общего назначения, не UI-специфичные).

**Контекст.** Движковый data-binding (`UiBind`) обязан оценивать биндинг ТОЛЬКО при
изменении источника (tick-сравнение). До этой волны в ядре: (а) change-ticks были только у
КОМПОНЕНТОВ — ресурсы (`Resources`) не несли тиков вовсе, «изменился ли ресурс» спросить
было нельзя; (б) прочитать тик компонента конкретной сущности вне `Query`-фильтров было
нечем (только `Changed<T>` внутри запроса или `DynItem::changed_since` на ВСЮ сущность);
(в) Lua-скрипты ходили к компонентам исключительно через отдельный typed-реестр
`Scriptable` — serde-tree путь инспектора (`ComponentSerdeFns` → JSON → merge →
`insert_dyn`) был им недоступен, каждый тип регистрировался дважды.

**Решения.**

1. **RT-1: change-ticks у ресурсов.** Слот ресурса несёт `TickCell` (дисциплина колонок):
   - стемп на `insert_resource`, на acquisition `&mut T` через эксклюзивный мир
     (`resource_mut`/`try_resource_mut` — взятие `&mut` из `&mut World` презюмируется
     записью) и на restore снапшота (восстановление = изменение);
   - **точный ленивый стемп у `ResMut<T>`** — только на `deref_mut` (аналог A13-дисциплины
     `Mut<T>`): система, декларирующая `ResMut<T>` и не писавшая в кадре, изменения НЕ
     создаёт. `ResMut::from_ptr` (мостовой конструктор) тиков не знает — change detection
     через него слепа, задокументировано;
   - чтение: `World::resource_changed_tick::<T>()` / по имени; сравнение —
     `Tick::is_newer_than(last_run)`; клампинг старых тиков — в общем
     `check_change_ticks` (та же защита от wrap, что у колонок).
2. **RT-1: ручной тик компонента.** `World::component_tick(entity, ComponentId)` /
   `component_tick_of::<T>(entity)` — чтение тика колонки конкретной строки для
   потребителей вне запросов (биндинги, тулинг). Внутри систем канон прежний — `Changed<T>`.
3. **RT-2: JSON-рефлексия ресурсов (read-only).** `World::register_resource_reflect::<R>()`
   + `resource_json_by_name` / `resource_changed_tick_by_name` (полное `type_name` или
   однозначный последний сегмент; неоднозначность — отказ, не угадывание). Ресурсы для
   рефлексивных потребителей — ИСТОЧНИКИ: запись остаётся типизированной. Реестр независим
   от снапшотного (E7, bincode).
4. **RT-2: serde-путь из Lua.** Глобалы `get_component(entity_id, name)` /
   `set_component(entity_id, name, partial_table)` — ТОТ ЖЕ механизм, что у
   `edit_setComponent` редактора: чтение всего компонента в JSON-дерево, partial
   **deep-merge** (канонический `apex_core::json_merge` — один на редактор/скрипты/движок),
   запись целиком через `deserialize_fn` → `insert_dyn` (тик стемпится — запись видна
   `Changed<T>`). Компоненту достаточно `register_component_serde_json` — БЕЗ per-type
   `Scriptable`-биндинга (два параллельных реестра остаются: typed-путь быстрее и умеет
   phase-B-доступ по колонкам; serde-путь — универсальный fallback). Чтение немедленное,
   запись отложенная (через `Commands` на sync-точке, как все скриптовые мутации);
   declared-access phase-B систем уважается и здесь (§0.2a — отказ громкий).

**Альтернативы, отклонённые.**
- Стемпить ресурс на acquisition `ResMut` (без ленивого deref) — каждая система с
  `ResMut<T>` в сигнатуре создавала бы ложное «изменение» каждый кадр; реактивные
  потребители получали бы шум.
- Версионировать ресурсы на стороне движка (обёртки/ручные dirty-флаги) — второй источник
  истины поверх ECS, каждая подсистема изобретает свой; тики — фундаментальное свойство
  данных мира, место им в ядре (прецедент Р-2б/ADR-008).
- Дать Lua доступ через дублирование инспекторного кода в движке — реестр уже в ядре,
  механизм один, копия разъехалась бы.

**Последствия.**
- `Resources::insert/get_mut/try_get_mut` получили параметр `tick` (внутрикрейтовые
  вызовы обновлены; внешний мир ходит через `World`-методы, сигнатуры которых не менялись).
- `ResourceSerdeFns::deserialize` принимает `Tick` (restore стемпит).
- Каждый `deref_mut` `ResMut` пишет u32 — стоимость одной записи, паритет с `Mut<T>`.
- Lua-sandbox дополнен `assert`/`error`/`pcall` (стандартные, безопасные) — нужны
  скриптам, работающим с fallible-API.
- Движок регистрирует UI-компоненты `register_component_serde_json` ⇒ рефлексивные
  биндинги/префабы/Lua получают их автоматически (см. движковый ADR фазы UI.5).
