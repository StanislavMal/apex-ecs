# ADR-023 — События эксклюзивной системы доходят до следующей стадии

Статус: принято 2026-10-25
Смежно: ADR-010 (запуск = прочтение), руководство §5.2 и §6, `compile.rs`, `executor.rs`

## Контекст

Полевой отчёт с интеграции ядра в игровой проект (Voxelia, этап 2; HEAD `fa4c459`). Эксклюзивная
система `apply_input` стадии `input` шлёт события `Explosion` и `Paint` через `world.send_event`,
эксклюзивная система `simulate_matter` стадии `matter` читает их через `world.event_reader`.
Читатель не видел ни одного события, а `pending` рос кадр за кадром: событие не становилось
читаемым никогда.

Руководство обещает обратное (§5.2): «`sched.run(&mut world)` автоматически флашит события
после каждого Stage… События, отправленные на Stage N, видны на Stage N+1 того же кадра».

Причина — в сборке плана. Флаш стадии переключает буферы только тех типов, которые системы стадии
объявили в `writes_event` (`compile.rs`, `stage.emit_event_types`). У эксклюзивной системы
(`SystemKind::Sequential`, `seq(..)`, `system!` с `world: &mut World`) дескриптора доступа нет:
`access()` возвращает `None`, и её события в список флаша не попадали. `World::tick()` событий не
флашит по контракту, так что без объявленного писателя тип не флашился вовсе.

## Решение

Стадия, в которой есть эксклюзивная система, после выполнения флашит **все** очереди событий
(`World::flush_all_events`), а не только объявленные типы: эксклюзивная система может отправить
событие любого типа через `&mut World`, и узнать какого — до запуска нельзя.

- `Stage::flush_all_events` — признак, выставляется в `compile()` по `access() == None` у любой
  системы стадии.
- Исполнитель во всех трёх местах флаша стадии (последовательный проход, SEQ-откат параллельной
  стадии, параллельная ветка) зовёт одну функцию `flush_stage_events`: все очереди, если признак
  есть, иначе — объявленные типы, как раньше.

Почему это безопасно для остальных событий: `Events::update` не теряет события, которые не
дочитаны объявленным читателем, — он их удерживает (гарантия «без потерь», ADR-010). Лишний флаш
типа, не тронутого стадией, — пустая операция (`pending` пуст, все курсоры на конце).

## Последствия

- Контракт руководства §5.2 выполняется и для эксклюзивных систем; ручной `flush_all_events()`
  в таких системах не нужен.
- Стадии без эксклюзивных систем флашат как раньше — по объявленным типам.
- Цена: стадия с эксклюзивной системой проходит по всем зарегистрированным типам событий
  (ранний выход на пустых буферах).
- Тесты: `exclusive_system_events_reach_the_next_stage` (эксклюзивный отправитель → эксклюзивный
  читатель, три кадра, каждое событие прочитано ровно раз) и `exclusive_event_reaches_a_declared_reader`
  (эксклюзивный отправитель → `EventReader<E>` следующей стадии).
