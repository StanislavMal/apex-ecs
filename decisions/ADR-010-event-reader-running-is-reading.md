# ADR-010: Семантика событий «запуск = прочтение» (running is reading)

**Дата:** 2026-07-16 · **Статус:** принято

## Контекст

No-loss-retention событий (козырь vs Bevy: гейтнутые системы не теряют события;
Bevy теряет ~33% при гейте из-за жёсткого 2-кадрового старения) был привязан к
条件 «каждый КУРСОР дочитал до конца». Курсор двигался только при явном
`.read()`. Система, которая **запустилась, но не читала** (ранний `return` в
теле — фокус не на том виджете, ресурс ещё не готов и т.п.), навечно
останавливала свой курсор и тем самым:

1. **Блокировала GC**: буфер `events` рос без предела (append-ветка
   `update()` никогда не очищалась).
2. **Пере-доставляла**: one-shot-ридеры (свежий курсор с 0 — `Listen`-путь
   AutoSystem, `event_reader_unchecked`) перечитывали удержанный буфер каждый
   кадр. Для сырого ввода это замораживало `Input::just_pressed` в `true` —
   любой игровой хендлер клавиши срабатывал бесконечно (найдено юзером на
   `ui_virtual_list`: клавиша A при фокусе списка спамила +1000 строк/кадр;
   виновник — `ui_text_input_system`, дренивший потоки только на пути
   `focus == None`).

Скрытый контракт «дрень свои ридеры на каждом early-return» — хрупкая
дисциплина, а не конструкция. Попутно: `EventReader` держал `*const`-указатель,
унаследовавший shared-borrow-тег от `&mut`, и мутировал через него в `read()` —
UB под Stacked/Tree Borrows (**MIRI-ER**, тот же класс, что закрытый MIRI-CD).

## Решение

**Курсор ДЕКЛАРИРОВАННОГО ридера двигается фактом ЗАВЕРШЕНИЯ ЗАПУСКА системы,
а не фактом чтения.** Три формы чтения:

| Форма | Курсор | Семантика |
|---|---|---|
| Declared (`EventReader<E>` param, `system!`-event, `Listen<E>`) | персистентный | exactly-once; **Drop обёртки в конце запуска = advance до конца буфера** (идемпотентно после `.read()`) |
| Gated (система не запущена планировщиком: run-condition, выключенная стадия) | персистентный, стоит | **no-loss**: события ждут запуска — козырь сохранён дословно |
| One-shot (`event_reader_unchecked`, `EventReader::new`) | свежий с 0, freed on drop | snapshot/инспекция; НЕ для side-effect-потребления (при чужом гейте перечитывает буфер — задокументировано) |

«Хочу копить» выражается **декларативно** (гейт планировщика), а не ранним
`return` в теле. Осознанное частичное потребление — queue-уровень
(`Events::read_partial` / `advance_reader_by`, владелец сам несёт retention).

Сопутствующее:
- **MIRI-ER закрыт**: `EventReader.ptr` теперь `*mut Events<T>` прямым кастом
  из `&mut` (провенанс записи сохранён); `iter`/`read`/`Drop` через него.
- **`Listen::fetch` → `event_reader_persistent_auto`** (стор курсоров ставится
  адаптером AutoSystem каждой системе — инфраструктура F4b уже была); движковые
  AutoSystems (apex-input) переведены с `unchecked` на `_auto`.
- **Starvation-диагностика (§0.2a)**: буфер, удержанный ≥64 тиков подряд, —
  rate-limited `warn!` (64→128→256…, тип события + длина + счётчик отстающих);
  дроп-cap **отвергнут** — тихо предал бы no-loss (resume-после-паузы обязан
  увидеть всё). Аксессор `Events::retained_ticks()`.

## Последствия

- Класс бага «забыл дренить» **непредставим**: движковый per-site дренаж в
  `ui_text_input_system` откачен, регресс-тест (`focused_non_text_widget_does_
  not_retain_keyboard_stream`, apex-ui) зелен БЕЗ него — приёмка корня.
- happy-path GC чаще прежнего (append-режим только при реальном гейте);
  AutoSystems больше не создают/удаляют курсор каждый кадр.
- Семантический слом (осознанный): «запустился-но-отложил» теперь = «прочитал и
  проигнорировал». Межкадровый peek через param-`.iter()` не удерживает
  (задокументировано на методе); аудит движка — живых пользователей не было
  (Tap-helper — standalone-курсор, не затронут).
- Тесты семантики: `persistent_reader_advances_on_drop_without_read`,
  `gated_reader_still_retains_events` (+ F4 no-dup, no-loss lagging — были).
  Miri: репро MIRI-ER + события — чисто.
