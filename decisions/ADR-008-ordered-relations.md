# ADR-008 — Упорядоченные relations: sibling order как публичная гарантия

**Статус:** принят 2026-07-13 (заказчик — движковая кампания UI_ARCHITECTURE, развилка Р-2б,
ратифицирована пользователем; см. apex-engine `plans/active/UI_ARCHITECTURE.md` и движковый
ADR-026).

**Контекст.** Список subjects пары `(kind, target)` хранился в порядке вставки, но удаление
использовало `swap_remove` (последний ребёнок телепортировался в дырку), `query_relation`
пересортировывал по (archetype, row), API управления позицией не было, а snapshot эмитил
связи subject-major — restore перемешивал порядок детей. Потребители страдали уже сейчас:
редактор ApexForge вёл собственный `SortKey`-компонент (второй источник истины порядка);
retained-UI (пейнт-порядок = порядок детей), слоты сцен и детерминизм требуют порядок как
свойство самой иерархии.

**Решение.**
1. **Порядок subjects — публичная гарантия для ВСЕХ видов связей** (без opt-in-флага: два
   класса поведения = два источника багов; ordered-remove — тот же O(fan-in) класс, что уже
   оплачиваемый position-скан). `add_relation` добавляет в конец; удаление — сдвигом, порядок
   остальных сохранён; эксклюзивный re-parent добавляет в конец списка нового родителя.
2. **API позиционирования:** `World::insert_relation_at` (ensure-at: нет пары — полноценный
   add со вставкой на позицию, есть — чистая перестановка), `World::set_relation_index`
   (только перестановка, `false` если пары нет), `World::relation_index` (чтение позиции).
   Перестановка — чистое изменение порядка: хуки add/remove не вызываются, счётчики индексов
   не меняются.
3. **Snapshot эмитит связи target-major детерминированно** (kinds ↑, targets по index ↑,
   subjects в sibling-порядке; `World::iter_relations_target_major`): restore добавляет связи
   в порядке списка ⇒ порядок детей round-trip'ится точно, wire-формат НЕ менялся. Exchange
   (`apex-isolated`) построен на snapshot/restore и наследует гарантию.
4. **Осознанное исключение:** `query_relation`/`query_wildcard` порядок не сохраняют
   (перегруппировка по архетипам ради скорости выборки) — задокументировано на API; «порядок
   + данные» = `targets_of` + точечный `get`.

**Последствия.**
- UI-дерево движка получает пейнт-/layout-порядок как свойство иерархии; редакторский
  `SortKey` подлежит миграции на ядро (отдельный заход в движке, не в этой кампании).
- Диффы снапшотов (`WorldSnapshotDiff`) сравнивают связи как МНОЖЕСТВО рёбер: чистая
  перестановка не попадает в дифф, `apply_diff` сохраняет старый порядок. Полные снапшоты
  корректны; долг диффа заведён в `plans/TECH_DEBT.md` ядра (loud-нота в коде).
- Байтовый порядок relations-секции существующих снапшотов при пересохранении изменится
  (subject-major → target-major); формат совместим, restore старых снапшотов работает.
