# CORE_ECONOMY — покадровая цена ядра пропорциональна изменённому

> **Назначение.** Закрыть реестр-блок PE-C1…PE-C7 (`plans/TECH_DEBT.md`, блок «движкового
> аудита PERF_ECONOMY», 2026-08-06): ядровой пласт «покадровая цена не пропорциональна
> изменённому», вскрытый четырёхсторонним аудитом движка (кампания движка PERF_ECONOMY,
> `apex-engine/plans/archive/PERF_ECONOMY.md` §1) и по её решению (§4 не-скоуп) вынесенный
> сюда — это правки хранилища/планировщика со своими бенчами и Miri-гейтами.
> **Открыта:** 2026-08-06. **Статус: волна 0 🔄.**
>
> **Центральный множитель — PE-C2**: поколонный агрегат тиков дешевит разом экстракт
> движка, `propagate_transforms` и ВСЕ `Changed`-системы обоих репо.

## Решённые развилки (пользователь, 2026-08-06)

- **Д-1 Точность агрегата: точный штамп через `Mut`** (а не консервативный бамп на
  `fetch_state` write-запроса). `Mut<T>` несёт указатель на агрегат колонки и на
  `deref_mut`/`set_if_neq`/`set_changed` делает второй store (relaxed). Цена: +8 байт на
  `Mut`, одна атомарная запись на мутацию — проверяется бенчами simple_iter/heavy_compute
  до/после. Альтернатива (бамп при взятии write-доступа) отвергнута: любой пер-кадровый
  `Write<T>` убивал бы скип всех своих архетипов — ровно в целевом сценарии (статика при
  живом аниматоре). → При ротации: ADR «поколонный агрегат тиков».
- **Д-2 Скоуп: весь пласт PE-C1…C7** одной кампанией (не только C2+C1).

## Дизайн PE-C2 (инварианты)

`Column` получает `max_change_tick`/`max_added_tick` — по `AtomicU32` (relaxed) на колонку.

- **Инвариант — верхняя граница:** агрегат «не старее» (в оконной семантике
  `Tick::is_newer_than`) любого построчного тика своей колонки. Тогда
  `!aggregate.is_newer_than(last_run)` ⇒ ни одна строка не пройдёт фильтр — архетип
  пропускается за O(1).
- **Атомик обязателен:** row-split чанки одной системы делят колонку; построчные тики —
  разные ячейки, агрегат — одна на всех (пишут одинаковый `this_run`, но по правилам Rust
  без атомика это гонка). Relaxed достаточно: значение одно, порядок не нужен —
  межсистемный порядок даёт планировщик (`AccessDescriptor`).
- **Пути записи, поднимающие агрегат:** `push` (spawn/insert), replace-insert,
  `push_moved_ticks` (archetype-move: агрегат приёмника поднимается до максимума
  переносимых тиков — иначе false negative, см. регресс-тест), `set_change_tick`,
  `stamp_range` (dense-слайс — один штамп на диапазон), `Mut::*` (Д-1).
- **`swap_remove` агрегат НЕ понижает** — консервативно: лишний скан, никогда не
  пропущенное изменение. Деградация скипа только в архетипах с чёрном (churn).
- **`check_change_ticks` клампит агрегаты** вместе с построчными (окно `MAX_CHANGE_AGE`).
- **Потребители:** skip-хук в `WorldQuery` (default «не скипать»); `Changed<T>`/`Added<T>`
  читают агрегат; кортеж скипает, если скипает ЛЮБОЙ конъюнкт; `Or` — только если ВСЕ
  ветки; `DynQuery`/`DynQueryMut` (changed-polling инспектора) — тот же путь; прямой
  тик-скан `propagate_transforms` — волна 2.

## Волны

- **Волна 0 🔄 — план + байзлайн.** Этот файл; бенч-варианты `changed_iter` static
  (0% мутаций) и fragmented (64 архетипа, мутируется один) — парно apex/bevy; байзлайн
  criterion: changed_iter (все варианты), propagate, simple_iter, heavy_compute —
  цифры в журнал ДО правок.
- **Волна 1 — PE-C2.** Агрегаты + все пути записи + skip-хук + DynQuery + тесты
  (обязателен archetype-move false-negative) + Miri (тик-пути = unsafe) + бенчи до/после.
- **Волна 2 — PE-C1.** Changed-фаза `propagate_transforms` (`transform.rs`): прямой
  тик-скан пропускает архетип по агрегату. `direct_tick_scan_matches_changed_query`
  остаётся зелёным; бенч propagate static-case.
- **Волна 3 — PE-C6.** Ресурсы: `Resources::get_mut`/`try_get_mut` не штампят при
  взятии — ленивый штамп (дисциплина RT-1/A13, как у `ResMut::deref_mut`);
  `ResMut::set_if_neq`; `FixedTime` без вечной «изменённости». Возможна тип-миграция →
  движковый гейт `cargo check --workspace --all-targets --all-features` (урок TD-203).
- **Волна 4 — мелочь.** PE-C3 (`any_with_component` — ранний выход по архетипам, не
  `count()`), PE-C4 (переиспользование арен команд — паттерн event-блоков D8b), PE-C5
  (identity-вектора `all_indices` ×5 в `executor.rs`), PE-C7 (rustdoc-формула интервала
  `check_change_ticks`).
- **Волна 5 — сквозной замер + ротация.** Пуш ядра ДО движка; замер экстракта/редактора
  движка (сверить LastWriteTime бинаря!); закрытие PE-C* в `plans/TECH_DEBT.md`;
  ротация плана → `plans/archive/` + ADR по Д-1; переоценить движковый TD-207
  (потребительская сторона).

## Гейты каждой волны

1. `cargo test --workspace` ядра зелёный; clippy net-neutral.
2. Miri по затронутому unsafe (тик-пути волны 1 — обязательно; точечный прогон — канон).
3. Движок собирается против локального HEAD ядра; при тип-миграции —
   `cargo check --workspace --all-targets --all-features` в движке.
4. Criterion: без регресса write-пути (simple_iter/heavy_compute) сверх шума; выигрыш
   целевых кейсов — числами в журнал.
5. Движковые goldens — только если дифф задевает render-путь (правки ядра сами по себе
   не задевают; сомнение = прогнать).
